# Trustworthy mosquito identification from sound on unseen sensors

**Status: closed 2026-11-02.** Start with `FINAL_RESULTS.md`.

A measurement and benchmark study on the BioDCASE 2026 Cross-Domain Mosquito Species Classification benchmark (CD-MSC): does a classifier's "90% sure" set-valued answer survive a change of recording sensor, why not, and what can be repaired?

## One-paragraph result

Standard split-conformal calibration covers only 17% to 36% of the true species on unseen domains at a 90% target (it hits 88% to 90% on seen domains). The cause is a sensor-to-species shortcut: unseen microphone recordings of three species are labelled as the three *Anopheles* species that exist only in microphone training data. Calibrating on held-out species-sensor groups restores coverage (0.93 to 1.00) but only by returning 7 to 9 of the 9 species; all rules lie on one coverage-versus-size curve, and no classifier we built crossed the sensor gap (best 0.27 unseen balanced accuracy against 0.31 for the challenge winner). A bounded positive: calibrating separately per detected sensor type gives 0.91 coverage at 2.6 species on the whole test, 24% to 46% smaller sets than a global threshold at matched coverage, though unseen groups still get 8 to 9 species.

## Repository layout

```
src/        every script, numbered by phase (p2a_..., p4_...), plus common.py
results/    reports, CSVs (results/csv), figures (results/figs), per-phase JSON and tables
configs/    placeholder; cdmsc_local.json is generated by src/baseline_features.py
notebooks/  Phase 0 setup and audit notebook
*.md        the written-up study (see the table above)
```

Not in the repository (too large, or generated): the dataset, the cloned baseline repo (`external/`), model prediction and embedding arrays (`*.npz`), run logs (`results/logs/`). The scripts regenerate them. Reported numbers are in the committed reports, JSON and CSV files.

## Reproduce (Python 3.13, CUDA GPU with 8 GB; developed on Windows)

```
pip install -r requirements.txt     # install torch/torchaudio for your CUDA version first
git clone https://github.com/Yuanbo2020/CD-MSC external/CD-MSC
```

Data (about 4.3 GB: `Development_data.zip`, `Evaluation_data.zip`) is downloaded by hand from Zenodo record 19095788 (the API returns 403 to scripts). `python src/extract_data.py <folder with the zips>` unpacks it into `data/cdmsc/` (default folder: `~/Downloads`). Run scripts from `src/`, one at a time (they need a lot of RAM). Each script is resumable.

1. `extract_data.py`, `phase0_audit.py`: unpack and audit the data.
2. `baseline_features.py`, `m1_predictions.py`, `m2_handcrafted.py`, `m3_ast_probe.py`, `phase1_conformal.py`, `phase1_diagnostics.py` (or `run_pipeline.py`): Phase 0 and 1.
3. `p2a_extract_ast.py --set all`, `p2a_head.py`: tiled 128-frame input (lost to the padded input).
4. `p2b_comp.py`: projection and alignment (no gain). `p2b_aug_extract.py`, `p2b_aug_eval.py`: audio augmentation (the one gain).
5. `p2c_calibrate.py`: group calibration. `p2b_bird_extract.py`, `p2d_bird_fuse.py`: Bird-MAE and fusion (no gain).
6. `p2g_perch_extract.py`, `p2g_perch_eval.py` (Perch 2.0 via a community PyTorch port; needs `pip install git+https://github.com/matijama/perch-v2-pytorch`), `p2e_seeds.py` (5 seeds), `p2f_bootstrap.py` (intervals), `p3_fewshot_figs.py` (few-shot and figures), `p4_mondrian.py`, `p4_figure.py`, `export_csv.py`.

Windows notes: scripts use a main guard and zero DataLoader workers; CPU matrix multiplies in numpy clash with torch's OpenMP runtime, so projections and SVDs run on the GPU.

## Honest limits

Two seeds for most ablations (5 for the key comparison); the unseen test was inspected during diagnosis, so claims about it are not clean (configuration choices used held-out folds only); evaluation labels are unreleased; Perch 2.0 run only through a community port that we did not verify against the official model; nothing here shows a deployable system.
